title: `and` does not force its right operand for a false left
grammar: typescript
asserts: types, values

The right operand is an unforced argument until the `case` on the left selects
it, so a diverging right operand is never evaluated under a false left. This
fixture pins the laziness obligation, not the truth table.

--- tql ---
loop x = loop x;
main = always $ false and loop 0;

--- source ---
class A {}

`loop` diverges if forced. A strict `and` would not terminate.

--- types ---
loop :: a -> b
main :: Node -> [Bool]

--- values ---
[false]
