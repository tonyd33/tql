title: an error that follows from one in the same definition is not reported
grammar: typescript
asserts: error

The mismatch in `1 + "a"` leaves its result poisoned, so `not` taking it is
not a second error, whether the result is used directly or through a local
binding (Static semantics: Errors).

--- tql ---
g = not (1 + "a");
h = let {
  k x = 1 + "a";
} in not (k 1);
main = pure 1;

--- source ---
class A {}

--- error ---
error[type-mismatch]: Expected `Int`, found `String`.
 --> 1:14
  |
1 | g = not (1 + "a");
  |              ^^^

error[type-mismatch]: Expected `Int`, found `String`.
 --> 3:13
  |
3 |   k x = 1 + "a";
  |             ^^^
