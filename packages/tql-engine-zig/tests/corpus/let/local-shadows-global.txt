title: a local binding shadows a global definition
grammar: typescript
asserts: core, types, values

Resolution is lexical first, then global. The local `label` wins inside the
`let` body. The global `other`, defined after `main`, still resolves `label` to
the global binding, so shadowing is lexical rather than dynamic. `other` being
declared later also exercises forward reference.

--- tql ---
import Data.Function (const);

label = "global";
main =
  let { label = "local" }
  in const [label, other];
other = label;

--- source ---
class A {}

--- values ---
["local", "global"]

--- types ---
label :: String
main :: Node -> [String]
other :: String

--- core ---
label = "global"
main =
  let label = "local" in
  const (Cons label (Cons other Nil))
other = label
